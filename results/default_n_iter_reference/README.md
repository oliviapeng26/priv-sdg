# Results at the uncapped default `n_iter` (reference)

Snapshot taken 2026-08-16, immediately before both GANs were capped at
`n_iter = 50` and regenerated. **These are not the headline results** — the
current ones live one directory up. They are kept because they are the
*uncapped reference* the capping decision rests on.

At the time of this snapshot:

- CTGAN and DPGAN were generated at the synthcity default (`n_iter = 2000`
  with `patience = 5`, so early-stopped in practice).
- BN and PrivBayes have no `n_iter` at all, so their rows here are identical
  to the current ones and carry no extra information.

## What these numbers are for

| | uncapped (here) | capped at 50 (current) |
|---|---|---|
| CTGAN TSTR | 0.874 ± 0.002 | ~0.866 expected |
| DPGAN TSTR | 0.526 ± 0.105 | ~0.472 expected |
| CTGAN generation | ~1542 s/run | ~196 s/run |
| DPGAN generation | ~1119 s/run | ~152 s/run |

Two claims in the write-up depend on the left-hand column:

1. **Capping costs little utility.** CTGAN loses ~0.009 AUC; DPGAN's drop sits
   well inside its own ±0.105 run-to-run spread.
2. **Capping is what makes multi-seed privacy audits affordable.** The
   generation cost alone falls ~8x, and the privacy audit scales with it.

The DPGAN column is also where the run-to-run spread is most visible: five draws
at this setting spanned [0.354, 0.632], one of them *below* 0.5, i.e. the
synthetic data was anti-predictive on the real test set.

## Provenance

All measured on the uni GPU workstation (statistical generators on CPU, neural
on CUDA — see the `device` column of `computational_cost.csv`). Generated by
`sdg/generate_runs.py` before the `GAN_N_ITER = 50` cap was added, and scored by
`evaluation/eval_fidelity.py` / `eval_utility.py`.

The synthetic data these were computed from is backed up at
`synthetic_data/runs_default_backup/` (gitignored, local only).
